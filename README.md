# AniShelf · 番选

带动漫封面的全库找番、综合评分与个性推荐网站。React + TypeScript 前端，Go 标准库后端，无需数据库。

## 启动

在本目录运行（Go 1.24 或更新版本）：

```sh
go run ./cmd/server
```

打开 http://127.0.0.1:8787/ 。已附带编译好的 `frontend/dist` 和真实评分快照，首次启动无需安装前端依赖。

仓库只包含公开评分数据与程序文件。B 站追番记录、片源运行缓存和本地截图保留在本机，不会提交到 GitHub；克隆后打开作品时会按需重新查找片源。

开发前端：

```sh
cd frontend
pnpm install
pnpm build
```

后端检查：`go test ./...`。

## 实时采集

服务运行期间，默认每 30 分钟尝试更新。页面“立即更新”可主动启动抓取，并每 4 秒读取进度；后台完成后片库与推荐自动刷新。抓取任务不会叠加，手动触发至少间隔一分钟。通过 `-refresh-interval 10m` 调整周期，`-refresh-interval 0` 关闭自动采集。

数据通过 Bangumi 公共 API、Jikan（MyAnimeList 的第三方只读接口）和 AniList GraphQL 获取，不依赖登录或绕过访问限制。逐条更新已收录作品评分，并尝试发现当前年份的作品：仅自动合并原始日文名称规范化后完全相同、且两个平台都有有效评分的日本动画。不同季与分割放送不会靠模糊标题拼接。

请求限速、超时重试、连续失败熔断；上游失败保留最近有效分数并展示提示。页面显示最后成功采集时间，作品详情保留各来源日期。更新频率不代表平台数据无延迟，尤其 Jikan 本身可能缓存。

一次性刷新：`go run ./cmd/server -refresh`。不要与正在运行的服务器同时刷新同一个数据文件。

## 综合评分

归一化到 10 分，按各平台评分记录数计算权重 `n / (n + 500)`，再加权平均。至少两个有效来源才给综合分，不把评分人数简单当成平台重要性。此规则是本站自定义方法，不是官方评分。排名仅限本站片库。

## 找动漫与综合榜单

首页「找动漫」直接搜索 Bangumi 动画库，也可按年份浏览，不受本站精选评分榜的收录限制。搜索支持「第2季」与「第二季」等中文写法，也将「蓝色禁区」映射到《蓝色监狱》的正式检索词；按 Bangumi 独立条目展示不同季和分割放送。搜索结果携带封面、首播日期、集数及 Bangumi 原始评分，10 分钟内的重复查询从内存缓存返回。

「综合榜单」是单独入口，保留本站多来源评分抓取与排序。全库搜索出的作品如果没有至少两个有效评分来源，只显示 Bangumi 原始分数，不伪造综合分。全库作品也可以加入本机浏览器的想看清单，并用作个性推荐的偏好信号。

## 个性推荐

“为你推荐”支持类型偏好。作品详情可标记喜欢、已看、不感兴趣，想看清单也作为弱偏好。Go 后端采用类型内容相似度结合综合口碑排序，每条展示推荐理由；已有喜欢、收藏、已看、不感兴趣记录的作品不重复推荐。没有偏好时先推荐高口碑作品。

偏好与片单保存在当前浏览器 localStorage，传给本机 Go 服务计算；没有账户体系和跨设备同步。当前为内容推荐，尚未实现基于大量用户行为的协同过滤。

## 数据范围

附带 43 部作品的多来源评分快照，包含经典作品与 2026 年作品；这是综合榜单的样本，而非找番的搜索范围。每次评分采集可补充严格匹配的当前年份作品。封面由来源平台图片地址加载。

Anime Trending 与 Anime Corner 为粉丝投票榜，页面提供外链，未计入综合评分。

## 接口

- `GET /api/explore?q=...&year=...&offset=...&limit=...`：Bangumi 动漫库实时搜索或按年份浏览
- `GET /api/explore/{id}`：全库动漫详情
- `GET /api/anime`：精选评分库搜索和类型、年份、评分筛选
- `GET /api/anime/{id}`：作品详情
- `GET /api/sync`：采集进度、问题与成功时间
- `POST /api/sync`：启动异步采集
- `POST /api/recommendations`：接收 genres、liked、saved、seen、disliked，返回最多 12 部作品与推荐理由

默认仅监听本机。数据存储于 `data/catalog.json`，后台使用原子替换保存；可以通过 `-data`、`-web`、`-addr` 指定路径或地址。

## B 站追番导入与自动化

在“为你推荐”输入自己的 B 站数字 UID 或 `https://space.bilibili.com/UID` 链接，选择同步周期，点击“连接并导入”。后台分页读取番剧追番（不包括国创与电影分区），保存想看、在看、看过状态；每 24 小时自动获取一次，可改为 6 / 12 小时或关闭。手动同步至少间隔 5 分钟。任务和记录存于 `data/bilibili.json`（权限 0600），重启服务后会补跑到期任务。Go 服务停止时不会执行任务；这是应用内定时任务，不是 Codex 提醒。

接口使用 B 站空间追番端点 `/x/space/bangumi/follow/list`，该接口不是稳定开放平台承诺，可能返回隐私限制或风控。失败、超时、分页不完整时不覆盖上次成功记录，也不绕过访问限制。实现参考 [追番接口字段记录](https://github.com/realysy/bili-apis/blob/master/docs/user/space.md)，并验证了实际接口会返回隐私限制代码。

公开追番优先，不需要密码。对于自己的私有追番，可在本机启动 Go 服务前设置环境变量 `BILIBILI_SESSDATA` 为本人登录会话值；后端仅随请求发送给 B 站，不写入配置文件、不返回前端、不输出日志。请勿把登录会话值发送到聊天中。登录过期后需要本人更新本机环境变量并重启服务；当前没有二维码登录或自动续期功能。

名称采用规范化后的严格匹配，中文、日文和英文标题均可；重复或歧义标题不自动合并。待匹配条目可在“查看追番与修正匹配”中选择本站作品，修正会保留到下一次同步。选择“未匹配 / 不用于推荐”会显式排除该条目。推荐时追番会再与扩大的候选池匹配，能覆盖更多作品；仍未匹配的记录不猜测类型，不会把私有追番标题逐条发送给 Bangumi 搜索。

类型画像按已匹配的不同作品统计，一部作品可属于多个类型，因此计数不是互斥百分比。B 站追番作为弱兴趣信号：想看 0.6、在看 1、看过 1.2；不会当成点赞。手动喜欢权重 3，收藏权重 1，不感兴趣优先覆盖追番兴趣，所有已追番匹配作品从候选推荐中排除。

推荐采用 **TF-IDF 特征向量 + 加权用户画像 + 余弦相似度 + MMR 多样性重排**。候选池除了综合榜单，还从 Bangumi 按热度读取有足够评分的日漫，并按最多两个兴趣标签补充候选；每页结果缓存 30 分钟。特征包含类型、制作公司（基础权重 0.45）、作品形式（0.2），按候选池中出现频率降低常见特征权重。个性排序为 `0.72 × 兴趣相似度 + 0.28 × 口碑质量 − 0.15 × 不感兴趣相似度`，再结合相似度与同系列前缀惩罚减少续作扎堆。多站作品的口碑质量来自综合分；单站作品使用按评分人数向 7 分收缩的 Bangumi 分数，只用于排序，页面仍显示原始 Bangumi 分数。上游失败时退回可用候选。权重为可解释的产品默认参数，未声称通过用户数据训练或验证；不是喜欢概率，也没有协同过滤。

本地应用目前面向单个使用者：B 站账号和同步记录是 Go 服务的一个本地配置，不是多用户账号系统。手动偏好仍保存于各浏览器。

新增接口：

- `GET /api/bilibili`：同步状态、追番记录、匹配覆盖率、类型画像
- `POST /api/bilibili/config`：`uid` 与 `intervalHours`（0 / 6 / 12 / 24）
- `POST /api/bilibili/sync`：手动启动后台获取
- `POST /api/bilibili/match`：`seasonId` 与 `animeId`，手动修正匹配

## 中文在线片源与站内自动播放

Go 后端从 AGE、iKun 和樱之空（skr1.cc）的公开搜索、详情与选集信息采集中文播放来源。按原版名称或完整中文别名及年份核对作品和季数，避免匹配错季度。打开作品详情时，按需读取 Bangumi 条目的正式别名并缓存 24 小时；精选评分库的综合评分会保留，Bangumi 暂时不可用时回退到本地快照。AGE 每 6 小时更新精选片库，也可手动更新；iKun 和樱之空在打开作品详情时按需核对，结果缓存 24 小时。失败保留上次数据。全库搜索打开作品详情时会按需查找对应季度的片源并存入快照。AGE 若使用罗马数字而 Bangumi 使用中文季名，先扩大到系列名搜索，再以原版名称严格核对。片源采集成功不等于每条视频线路都能播放。

部分源站线路使用加密播放器配置，本站只读取可直接访问的 HTTPS 视频地址，不破解加密配置或会员验证。解析同一集时把「第01集」「第1集」「第01话」「第01回」视作同一集，一次最多尝试 6 条线路，并优先覆盖不同站点。电影有完整版本时，选集列表隐藏 TC/TS 预览版本。AGE、iKun 与樱之空的元数据请求分别共享至少 1.5 秒的间隔，媒体探测按域名至少间隔 1 秒，视频代理按域名至少间隔 250 毫秒且最多 4 个并发请求；对 429/503 及同一域名重复 403 按 `Retry-After` 或默认 10 分钟退避，被拒绝的单条线路也缓存 10 分钟。三个站点的冷却截止时间分别保存在 `data/age-playback.json.cooldown`、`data/age-playback.json.cooldown.ikun` 和 `data/age-playback.json.cooldown.skr`，服务重启也不会立即重复请求。退避期间页面显示 AGE 剩余冷却时间并禁用手动更新。它降低请求强度，但不能保证源站不会限制访问。

播放链路为：已收录选集 → Go 读取 AGE 或樱之空的公开播放器配置，或 iKun 公开直链 → 核验 HTTPS HLS 主清单、子清单与首个视频分片（或直接视频响应） → 注册短期播放会话 → Go 转发清单与分片 → 本站 HTML5 / hls.js 播放器。源站请求使用正常页面来源信息；不载入其完整网页或第三方播放器脚本。打开作品时先按需补查其他来源，再开放选集；用户只需选择集数：后端先核验线路并自动选源，浏览器实际播放失败时上报该线路、短期排除并重试，界面标出当前来源。无法直接解析的线路保留错误说明，不解密混淆配置或视频 DRM。

接口：
- `GET /api/playback`：采集结果与进度。
- `POST /api/playback/sync`：发起后台更新。
- `POST /api/playback/lookup/{id}`：按需匹配一个全库作品的准确季度选集。
- `GET /api/playback/resolve?animeId=...&episode=...`：按集数自动选源，返回视频类型、本站视频地址与实际线路；原有 `path` 参数仍兼容。
- `POST /api/playback/failure`：播放器遇到致命错误时报告已收录线路，短期排除后自动重试。
- `GET /api/playback/media/{token}?url=...`：短期会话内转发对应 CDN 的清单和分片，支持 Range / Content-Range；清单中的相对 URL 与 URI 属性改写为本站地址。

媒体会话有效 2 小时，最多 256 个；代理限制到对应作品的视频目录，校验 HTTPS、跳转范围及实际连接 IP，拒绝内网与本机地址。iKun 清单已核验会把分片放在 `kkzycdn.com:65`，仅对 `bfikuncdn.com` 入口会话允许这一跨 CDN 域名与同集目录；清单中明显以不连续标记分隔、引用其他作品目录的插入片段会被跳过，代理仍只允许请求本集目录。不能作为任意 URL 的开放代理。片源更换 CDN、动态签名或配置时可能需要后续适配。播放消耗 Go 服务带宽。

前端支持中文选集、自动切换线路、全屏和当前浏览器断点续播；hls.js 在需要时加载，不影响首页初始加载。本站不插入广告、不执行源站广告脚本，但会保持视频自身内容，源视频可能包含插播广告。字幕以实际视频为准。

实现参考：[AnimeDownloader](https://github.com/theamusing/AnimeDownloader) 的“解析实际视频地址 + 本地转发”思路；[agefans-enhance](https://github.com/IronKinoko/agefans-enhance) 主要是在源站增强播放器，不等同于跨网站接入。本项目用 Go 自行实现后端，前端使用官方 [hls.js](https://github.com/video-dev/hls.js)，未运行第三方仓库代码。

扩展片源时参考 [Kazumi](https://github.com/Predidit/Kazumi) 的规则化片源模块思路：每个来源独立搜索、核对作品身份、记录线路状态，只有实际可访问的媒体才进入自动播放。曾低频检查 360 资源站与樱花资源的公开接口：前者在抽查中有分类错误及缺片，后者当前返回 403，因此没有把未经核验的结果展示为可播片源。
